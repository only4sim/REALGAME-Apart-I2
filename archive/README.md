# Historical provenance archive

`history.zip` preserves the original bytes of historical evidence, reports, source snapshots and preparation records. `INDEX.json` maps their original paths to SHA-256-addressed ZIP members. Identical bytes are stored once. This archive is historical provenance, not a current paper or an executable default working tree.

The cleanup started from the Git commit recorded in the index. It consolidated 2,581 logical paths into 410 distinct content objects. The active repository no longer contains the full v6 clone, nested provenance copies, duplicate CPU outputs, historical mock directories, obsolete agent instructions, stale root PDF/DOCX/Markdown or old generated release ZIPs. Canonical current evidence remains under `results/`.

## Recover or verify

```bash
python3 scripts/restore_history.py --verify
python3 scripts/restore_history.py \
  --path submission_report.pdf --out build/history/v7-report.pdf
python3 scripts/restore_history.py \
  --path verification/v7/source_audit.json --out build/history/v7-source-audit.json
```

Output paths must be fresh. Nothing is restored automatically during normal reproduction. To find an exact historical key, search the JSON index with `rg`; nested original ZIP members use `old-archive.zip!/member/path` keys.

All old ZIP member bytes were preserved. The obsolete ZIP containers themselves are not stored again; their original hashes and exact Git recovery commands are in the index. Generated bytecode and empty runtime locks were discarded. Raw observations were not edited, synthesized or relabeled.

Both the standalone index and its copy inside the ZIP are checked, along with every distinct object's hash. A historical file remains historical even if recovered to a new path; old frozen cohorts must not be resumed with changed code or reused approval.
